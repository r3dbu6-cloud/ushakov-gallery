# Галерея Святослава Ушакова

Статическая галерея для публикации на Netlify с каталогом в Supabase.

## Защищённый режим автора

Вход расположен по адресу `/author/`. Пароль не хранится в репозитории:
аутентификацию по паролю или одноразовой ссылке выполняет Supabase Auth,
а возможность сохранять раскладку проверяется политиками Row Level Security.

Старый `/admin/*` на Netlify принудительно перенаправляется на `/author/`.
Его клиентский пароль больше не используется как средство защиты.
Миграция также отзывает у браузерных ролей прямую запись в `paintings`,
`orders` и Storage, поэтому старые клиентские методы не смогут изменить данные
даже при прямом вызове API.

### 1. Применить миграции

В production обе миграции уже применены. Для нового окружения сначала выполните:

`supabase/migrations/202607260001_secure_catalog_author.sql`

Затем создайте учётные записи владельцев в Supabase Auth и выполните:

`supabase/migrations/202607260002_assign_catalog_authors.sql`

Вторая миграция назначает роль `author` двум утверждённым email и атомарно
останавливается, если хотя бы одной учётной записи ещё нет. После изменения роли
нужно выйти и войти заново, чтобы получить свежий JWT. Роль хранится в
`app_metadata`, которую пользователь не может менять из браузера.

### 3. Настроить Supabase Auth

В Authentication → URL Configuration добавьте:

- Site URL: `https://www.slavaushakov.gallery`;
- Redirect URL: `https://www.slavaushakov.gallery/author/`.

Самостоятельную регистрацию пользователей можно отключить: автор создаётся
только администратором Supabase. Для учётной записи без известного пароля
используйте кнопку «Получить ссылку на email».

### 4. Опубликовать на Netlify

Подключите репозиторий к Netlify. Настройки уже находятся в `netlify.toml`:

- build command: `npm run build`;
- publish directory: `dist`;
- `/author/` не кэшируется;
- добавлены базовые security headers.

После публикации:

1. Откройте `/author/`.
2. Войдите пользователем с ролью `author`.
3. Измените порядок или разделы.
4. Нажмите «Сохранить каталог».
5. Откройте сайт в приватном окне и проверьте опубликованную раскладку.

Форма заявки должна записывать `orders` внутри Edge Function `send-order`
через серверный `service_role`. Если функция пытается писать от роли `anon`,
после безопасной миграции это будет запрещено — такую функцию нужно исправить
до production-публикации.

`catalog-config.json` остаётся резервной конфигурацией, если таблица Supabase
временно недоступна или ещё не содержит строки `main`.
